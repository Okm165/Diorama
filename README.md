# Diorama

Two blockchain **mirrors** on one Kubernetes cluster, the shared crates they
run on, and the CCTP bridge between them:

- **diorama-mainnet** — an Ethereum mirror: reth + a local Lighthouse, a
  fork-mode anvil (`anvil-t`), and the engine that follows the chain;
- **diorama-venue** — a HyperEVM mirror: a fork-mode anvil (`anvil-v`), the
  venue engine (follow + bridge + shadow registry), and the venue simulator
  (the market/account plane the test harness drives);
- **diorama-cctp** — the standalone bridge that relays burns between the two
  mirrors.

Every deployment value lives in two gitignored files per instance; everything
tracked is a template that boots unchanged on another machine.

## Boot a stack (from a fresh clone)

One command per instance:

```sh
make up INSTANCE=diorama-venue    # the venue mirror (engine, anvil-v, venue-sim)
make up INSTANCE=diorama-mainnet  # the Ethereum mirror (reth, lighthouse, anvil-t, engine)
make up INSTANCE=diorama-cctp     # the bridge (needs CCTP_RELAY_KEY=0x… in the env)
```

Prerequisites:

- a single-node **k3s** cluster reachable by `kubectl`
  (`KUBECTL`, `CTR`, `SUDO`, `RUNTIME` and `K3S_STORAGE` in the `Makefile`
  override the plumbing if your box differs — they default to
  `kubectl`, `sudo k3s ctr`, `podman`, `/var/lib/rancher/k3s/storage`);
- `podman` (or `docker`) and a Rust toolchain for `cargo`-based gates;
- `make up` builds every pinned image, imports it into the cluster's
  containerd store, creates the namespace + StorageClass, and applies the
  instance's overlay. The first run is a full build; later runs are no-ops.

Then watch it come up:

```sh
make INSTANCE=diorama-venue status     # pods, PVCs, engine status
make INSTANCE=diorama-venue logs       # follow every pod's log
make venue-smoke                       # the venue's end-to-end smoke test
```

Reach the services from the host with the loopback port-forwards the overlay
already documents (`k8s/overlays/*/nodeports.yaml`) and source the endpoints
env the consumer harness reads:

```sh
kubectl -n diorama-venue port-forward --address 127.0.0.1 svc/anvil-v 31545:8545 &
kubectl -n diorama-venue port-forward --address 127.0.0.1 svc/engine 31880:8080 &
kubectl -n diorama-venue port-forward --address 127.0.0.1 svc/venue-sim 31090:8090 31091:8091 &
source <(kubectl -n diorama-venue get cm test-endpoints -o jsonpath='{.data.test-endpoints\.env}')
```

## Deployment data (the two files that are never committed)

Each instance reads exactly two untracked files. `make config-bootstrap`
creates both from their tracked templates whenever they are missing, and
`make apply` runs it first — a fresh clone cannot apply a half-configured
stack.

| file | template | what it carries |
| --- | --- | --- |
| `config/instances/<instance>/specialization.toml` | `specialization.example.toml` | the instance's TOML mounted at `/etc/mirror`: endpoint capability claims, watch scope, fixtures, markets, the fork pin |
| `k8s/overlays/<instance>/wiring.env` | `wiring.example.env` | the cluster wiring every pod's env resolves: the fork source URL, the market plane, service DNS, state roots |

Secrets are neither file: the CCTP relay key is created once with
`make cctp-secrets CCTP_RELAY_KEY=0x…`, the mainnet's reth↔lighthouse JWT is
generated by `make mainnet-secrets`. Never put a key in a tracked manifest or
a tracked config.

## The config layering

`config/defaults.toml` → `config/instances/<instance>/instance.toml` →
`specialization.toml`, with `${VAR}` references expanded from the pod's env
(the `wiring.env` ConfigMap). Validate the result without a cluster:

```sh
make config-check
```

## Development gates

```sh
make ci        # cargo test --workspace, then the structural gates
make lint      # clippy, all targets, warnings are errors
make ast-scope # fn/struct size and nesting analysis
```

## Ops (read-only first)

```sh
make INSTANCE=diorama-venue status     # pods, PVCs, engine status
make mirror-freshness                  # every plane's lag in one view
make substrate-attest                  # read-only substrate invariants
make logs-check                        # warnings/errors per component, normalized
```

Drills and repairs (re-pins, snapshots, blob pruning) are the
`mainnet-*` / `venue-*` targets in `make help`; each is idempotent and states
its own prerequisite in its header comment.
