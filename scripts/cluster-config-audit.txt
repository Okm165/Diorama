# The live-vs-repo config audit (re-measured 2026-11-17), kept as a gate.
#
# One line per key the LIVE cluster's pods resolve, as a dotted path into the
# merged effective config (defaults <- specialization <- instance):
#
#   namespace|dotted.key|class
#
# class live-read : a pod of that namespace resolves the key from the merged
#                   config - the tracked tree must carry it (through the live
#                   specialization, or the shared defaults), or a fresh clone
#                   loses a live fact.
# class live-dead : no reader anywhere - the build must NOT carry it back;
#                   the value's real home is named in the comment beside it.
#
# The other direction - every specialization key must have a reader - is not
# this file's job: the typed loader refuses an unknown key at every level
# (`deny_unknown_fields`), so `make config-check` fails on a key nobody
# reads. The specialization cannot grow dead weight silently.
#
# The mounted-file keys themselves (instance.toml, specialization.toml) are
# gated by the build check in config-lint.sh rule 3: the instance unit's
# generator fails the build when the specialization file is absent, so a
# ConfigMap can never silently lose its source.
#
# The third-party chain nodes' own settings are manifest literals now, not
# configuration (the lighthouse checkpoint-sync URL in
# k8s/base/diorama-mainnet/lighthouse.yaml; the reth snapshot source is
# reth's own default) - they are audited by reading the manifests, not this
# file.
#
# diorama-mainnet: the wiring env map is gone; every key it carried lives in
# the specialization (endpoints, state root, JWT path) or the defaults.
